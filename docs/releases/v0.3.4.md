# OmniNexus 0.3.4

发布日期：2026-11-11

本版本修复一份私下提交的安全报告：自定义提供方的「测试连接 / 发现模型」端点可被用来把
已保存的 API Key 发往攻击者指定的地址，同时构成 SSRF 通道。

## 1. 修复内容

### P0 · 已存密钥与可覆盖 URL 解耦

| 端点 | 修复前 | 修复后 |
| --- | --- | --- |
| `POST /v1/custom-providers/test` | `body.id` → 复用已存密钥，URL 由 `body.baseUrl` 决定 | 仅当 `baseUrl` 与已存地址一致才复用密钥 |
| `POST /v1/custom-providers/{id}/test` | `body.baseUrl` 覆盖 + `snapshot.api_key` | 忽略 `body.baseUrl`，只用已保存 URL |
| `POST /v1/custom-providers/discover-models` | 同 test | 同左规则 |
| `POST /v1/custom-providers/{id}/discover-models` | 同 test | 同左规则 |

规则总结：

- **已保存的提供方**只在**自己的 URL** 上测试；
- **覆盖 Base URL** 时必须显式提供 `apiKey`，否则不带 `Authorization` 头；
- 不再出现「URL 来自请求体、密钥来自数据库」的组合。

### P1 · 出站 egress 策略

新增 `providers/network.py`：

- 拒绝回环、RFC1918 私网、链路本地（含 `169.254.169.254`）、ULA、组播、保留地址、
  `0.0.0.0`、`::`，以及 IPv4-mapped IPv6；
- 对主机名做 DNS 解析，**校验全部 A/AAAA 记录**；
- 把通过校验的 IP **pin 到实际连接**（`sni_hostname` 保持证书按主机名校验），
  避免「先校验、后按主机名建连」被 DNS 重绑定绕过；
- `follow_redirects=False` 保持；
- 新增错误码 `EGRESS_BLOCKED`（HTTP 422），可诊断。

默认开启。本地模型用户需显式放行：

```yaml
server:
  allow_private_targets: true
```

### P2 · 缩小暴露面

- 绑定非回环地址且未显式放行时**拒绝启动**（`server.allow_insecure_bind` / `--allow-insecure` /
  `OMNI_ALLOW_INSECURE_BIND=1`）；
- `docker-compose.yml` 显式设置该开关（容器内必须绑 `0.0.0.0`，端口仍只发布到宿主回环）；
- 请求体上限不再只依赖 `Content-Length`：chunked / 无长度请求按实际字节数校验。

### 附带修复（安全报告第 7 节）

- 错误契约补齐：`OmniError.as_dict()` 现在产出 `request_id`，与 `X-Request-ID` 一致；
- SSE 兜底错误帧的 `retryable` 由 `true` 改为 `false`，与 JSON 路径一致；
- 非流式 `run_json` 从 SSE 帧重建错误时保留 `retryable`。

## 2. 影响与升级

- 默认回环部署、只用内置厂商或本地提供方的用户：**行为不变**。
- 使用自定义提供方「临时改 URL 测试」的用户：该 URL 现在需要同时填写 API Key；
  或改用未保存端点（`/custom-providers/test`）并显式给出 key。
- 使用 `http://127.0.0.1:11434` 等本地模型 URL 的用户：需开启 `server.allow_private_targets`。
- 绑定 `0.0.0.0` 的用户：需设置 `allow_insecure_bind`。

## 3. 回归测试

新增 `tests/test_provider_security.py`（24 例）与 `tests/test_hardening.py`（8 例）：

- 覆盖 URL 且不给 key → 出站请求**不带** `Authorization`；
- 已保存端点忽略 `body.baseUrl`，只访问已保存主机；
- 显式 key + 覆盖 URL → 密钥只发往该显式目标；
- 正常已保存测试仍使用已存密钥；
- `127.0.0.1` / `10.x` / `172.16.x` / `192.168.x` / `169.254.169.254` / `0.0.0.0` /
  `::1` / `fc00::1` / `fe80::1` / `localhost` 全部被拒；
- 开启 `allow_private_targets` 后恢复本地测试；
- 无 `Content-Length` 的超大 body 返回 413；
- 非回环绑定被拒绝，回环正常；
- 错误体在 400/422/503 下都含 `request_id` 与 `retryable`。
