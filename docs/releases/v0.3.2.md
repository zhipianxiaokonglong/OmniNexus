# OmniNexus 0.3.2

发布日期：2026-11-07

## 修复

对应 [Issue #1](https://github.com/zhipianxiaokonglong/OmniNexus/issues/1)：

- **可读的 422**：自定义提供方模型数超过 200 时，`error.message` 直接返回
  “模型数量超过上限：单个提供方最多 200 个模型，请减少模型后重试。”，
  `details.fields` 仍保留原始原因。
- **前端字段级错误条**：保存失败时在表单内持久展示首条字段错误，不再只靠 5 秒 toast。
- **发现模型截断**：`/models` 返回 566 个时，只加入剩余容量内的模型，并提示
  “另有 N 个模型超过 200 上限，未加入”。
- **计数与防卡顿**：模型区域显示 `当前 / 200`，达到上限后禁用“手动添加”，避免生成
  数百行 DOM。

## 不变

- 200 上限保留，不放宽；数据边界仍是 fail-closed。
- `discover-models` 接口仍返回上游全集，截断由前端负责。
- 不涉及密钥、数据损坏或越权。

## 数据目录

`OMNI_DATA_DIR` 必须是最终数据目录。OmniNexus 不会在其下再派生 `omninexus/`；若启动器
传入 `{data_dir}/omninexus`，数据库会落在该路径。双层空库应由启动器 manifest 修正为
`"{data_dir}"`。
